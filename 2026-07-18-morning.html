OpenSSL HollowByte: 11-Byte Payload Crashes Servers, Patched Silently With No CVE


Jul 17, 17:56


A vulnerability dubbed HollowByte, discovered by Okta's Red Team, allows an unauthenticated attacker to send an 11-byte TLS handshake payload that causes OpenSSL servers to pre-allocate up to 131KB of memory that is never released — effectively a heap exhaustion DoS. OpenSSL shipped the fix in June with no CVE, no advisory, and no changelog entry flagging the security relevance, meaning most operators patched it unknowingly or not at all. Okta's publication of the mechanism means weaponization is now straightforward for any attacker targeting unpatched OpenSSL deployments.


A silent OpenSSL patch for a trivially exploitable DoS — now public — means any server still running pre-June OpenSSL is exposed and operators may not know they need to act.

Capital One Open-Sources VulnHunter — Agentic AI Security Tool That Reasons Forward From Attacker Entry Points


Jul 17, 20:51
